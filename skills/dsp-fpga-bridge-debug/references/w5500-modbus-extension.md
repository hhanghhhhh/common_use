# W5500/Modbus TCP 可选扩展

只在任务涉及 W5500/Modbus TCP 上位机访问时读取。先区分黑盒收发验证和内部诊断，默认只执行用户要求的最短路径。

## 黑盒快速验证

用户已提供目标 IP、端口和待发送报文，且只问“能否通信/响应是否正确”时：

1. 直接对用户给出的 IP 执行有限次数 `ping`。
2. 建立 TCP 连接，发送用户指定报文；若只给出寄存器目标，则构造最小无副作用只读报文。
3. 校验实际响应的事务号、协议号、长度、Unit ID、功能码、异常码、字节数和数据；原始收发十六进制报文作为主要证据。
4. 按用户要求或最小必要次数重复，报告 `PASS/FAIL`、延时/timeout 和原始响应，然后停止。

该路径禁止自行扩展到源码搜索、EEPROM IP、网卡/ARP 枚举、DSS symbols、内部变量、心跳、socket/计数器、FPGA identity/bridge、重新编译或下载。只有 `ping`/TCP/协议响应失败，或用户明确要求内部诊断、固件下载、联合验证时，才执行后续分层流程。

用户同时要求 RAM 下载和黑盒通信时，把构建/下载交给 `ccs-c2000-debug`；下载成功后仍只用网络报文作为通信 PASS 证据，不附加内部状态验收。

“可以先烧写 RAM”“必要时可下载”等措辞只表示授权或备用方案，不等于必须下载。先测试板上当前服务；已经正确响应就停止。只有用户明确要求“先下载当前工程再测”，或当前服务不响应且下载属于已授权恢复动作时，才执行 RAM 下载。

## 分层

```text
PC 测试程序
→ Ethernet/W5500
→ Modbus TCP
→ DSP 白名单寄存器/命令邮箱
→ XINTF bridge
→ FPGA 状态或受控参数
```

DSS 负责装载、符号和底层诊断；Modbus 用于产品程序持续运行时的受控远程接口。不要把任意 XINTF 地址直接暴露为网络可写寄存器。

## 内部诊断

仅在黑盒验证失败或用户明确要求定位内部原因时执行：

1. 从运行时状态确认目标 IP、端口、PHY link 和一个无副作用只读寄存器；不要只信源码默认值。
2. 检查 PC 网卡、掩码、路由和 ARP 出口。
3. 先验证 TCP 连接，再发送最小功能码 03 只读请求。
4. 校验完整 MBAP/PDU：事务号、协议号、长度、Unit ID、功能码、异常位和字节数。
5. 用匹配板上程序的 `.out` 只加载 symbols，交叉检查 DSP 心跳、运行 IP、socket、接收/错误/复位计数。
6. 请求后确认服务仍 LISTEN、心跳继续增长，并重复多次。

ping 成功不等于 Modbus 正确；数据值为 0 也可能是合法响应。黑盒任务以 TCP 和协议包络为准；内部诊断任务再增加 DSP 证据。

## 发布接口

- 只读区：identity、map version、状态、错误、计数和遥测。
- 参数区：有范围检查的候选参数。
- 命令区：白名单动作、提交/完成序号、timeout 和错误码。
- bridge：执行实际 `DataR/DataW` 并回读生效值。

远程写入需要范围、权限、白名单、commit/done、timeout 和实际值回读。电源、保护、复位和非易失写入仍需额外板级条件。

## 容易误判

- symbols 必须与板上运行程序一致。
- 计数器需在启动时明确初始化并在正确分支更新。
- 首次探测不要使用写功能码。
- 多网卡/VPN 环境确认实际路由和 ARP 接口。
- 探测脚本设置连接/接收 timeout，并区分不可达、非法响应和协议 PASS。
- 最终同时验证仿真器连接状态和脱离仿真器独立运行状态。

上述 symbols、计数器和仿真器检查只属于内部诊断，不是黑盒快速验证的必做项。
