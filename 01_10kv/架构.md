# 架构设计说明书

## 1. 项目概述

本项目为一款基于 TI TMS320F28335 DSP 的工业级高精度采样与控制板卡。
核心业务逻辑为：通过 W5500 运行 ModbusTCP 协议与上位机交互，接收参数并配置数字电位计及硬件增益；上电后启动对 AD7982 的精确定时定点采样，在接收到 CAN 总线同步触发指令后开始计算区间平均值；采样过程要求严格固定的采样率且不消耗大量 RAM，最终将实时采样值和区间平均值通过 Modbus 寄存器供上位机读取。

## 2. 硬件外设资源分配策略

为了实现任务解耦与零抖动采样，DSP 外设资源进行如下严格划分：

| 硬件模块 | 连接外设/芯片 | 核心功能与配置 |
| :--- | :--- | :--- |
| **原生 SPI** (SPI-A) | W5500 | 专用于 ModbusTCP 通讯。主循环轮询处理，不占用实时资源。 |
| **McBSP-B** (SPI主模式) | TPL0501, AD5290 (DAC) | **普通 GPIO 充当片选 (CS)**。用于低频、非实时控制。支持总线复用机制动态切换时序。 |
| **McBSP-A** (SPI主模式) | AD7982 (18位 ADC) | 结合 **DMA** 使用，配置为 32-bit 字长接收。绝对禁止使用普通 GPIO 软件片选。 |
| **ePWM** | AD7982 (CNV管脚) | 作为 ADC 的硬件“节拍器”与 DMA 触发源，提供严格固定的 10kHz 采样时钟。 |
| **DMA 通道** | McBSP-A 接收端 | 配置为连续单点触发模式（Burst Size=1），将 32位数据搬运至内存单个变量。 |
| **CAN 控制器** | 外部同步设备 | 仅用作“发令枪”，接收同步报文，触发高优先级接收中断。 |
| **I2C** | AT24C512C (EEPROM) | 存储校准数据、系统掉电保存参数，主循环调用。 |
| **普通 GPIO** | 硬件开关 | 用于采样档位切换、增益切换、DA补偿开关及电平转换使能。 |

## 3. 软件运行架构 (Data Flow & State Machine)

软件系统彻底抛弃“定时器轮询”的思路，采用 **“事件驱动 + 硬件自动化数据流”** 的架构设计。

### 3.1 核心全局变量设计（零 RAM 消耗方案）

```c
volatile Uint32 Live_ADC_Value = 0;  // 供 Modbus 随时读取的【当前实时值】
volatile Uint32 Raw_ADC_Value = 0;   // DMA 硬件自动覆盖的【底层原始变量】
volatile Uint64 Sum_ADC = 0;         // 采样求和累加器 (64位防溢出)
volatile Uint32 Count_ADC = 0;       // 已采样点数计数器
volatile Uint32 Target_Count = 0;    // 目标采样点数 (由上位机下发时间推算)
volatile Uint16 Flag_Start_Avg = 0;  // 测算区间开启标志 (CAN触发)
volatile Uint16 Flag_Calc_Done = 0;  // 测算完成标志 (DMA触发)
volatile Uint32 Final_Average = 0;   // 最终求出来的【平均值结果】
```

### 3.2 任务执行引擎 (三层解耦)

系统分为**主循环（后台非实时任务）**、**中断层（前台实时任务）**和**硬件自控层（零CPU占用）**。

#### A. 硬件自控层 (Hardware Automation)

* **链路**：`ePWM 定时匹配 -> 触发 ADC 转换 -> ADC 输出数据 -> McBSP 自动产生时钟接收 -> 触发 DMA 搬运 -> 写入 Raw_ADC_Value`
* **特性**：上电即刻开启，不受任何软件阻塞影响。实现了对 18位 ADC 的完美固定频率盲采。

#### B. 中断实时处理层 (ISRs)

1. **CAN 接收中断 (触发同步)**
    * **触发条件**：收到特定的同步报文。
    * **业务逻辑**：清空累加器 `Sum_ADC = 0`，清空计数器 `Count_ADC = 0`，置位标志 `Flag_Start_Avg = 1`。
    * **耗时控制**：< 1µs，立即退出。
2. **DMA 接收中断 (数据汇聚与测算)**
    * **触发条件**：DMA 每次搬运完 1 个采样点（2 个 16-bit 字）后触发。
    * **业务逻辑**：
        1. 移位掩码提取真实 18位数据：`(Raw_ADC_Value >> 14) & 0x3FFFF`。
        2. 更新实时单点变量 `Live_ADC_Value`。
        3. 判断 `Flag_Start_Avg == 1`：若成立，则将数据累加至 `Sum_ADC`，并自增 `Count_ADC`。
        4. 当 `Count_ADC >= Target_Count` 时，关闭累加窗口，置位 `Flag_Calc_Done = 1`。
    * **耗时控制**：仅做加法和判断，< 1.5µs，立即退出。

#### C. 主循环业务层 (While 1)

负责处理所有耗时、非实时且复杂的逻辑：

1. **ModbusTCP 轮询**：解析上位机读写寄存器请求。
2. **复杂数学运算**：检测到 `Flag_Calc_Done == 1` 时，执行除法 `Final_Average = Sum_ADC / Target_Count`，并清零标志位。（除法耗时较长，隔离在主循环可保障系统实时性）。
3. **DAC 动态配置 (总线复用)**：当上位机下发数字电位计参数时执行。

## 4. 关键模块底层设计规范

### 4.1 18位 ADC 的 DMA 接收读取机制

* **位宽限制突破**：F28335 DMA 读取 McBSP 寄存器物理限制为 16-bit。必须配置 McBSP 接收字长为 32-bit（`RWDLEN1=101b`）。
* **Burst 机制**：DMA 配置为每次触发产生突发（Burst Size = 1），连续读取 `DRR2`（高16位）和 `DRR1`（低16位），目标地址步进设为 1，将其组合至 32位 内存单元中。

### 4.2 McBSP 控制双 DAC 的总线复用规范

在主循环中，控制 TPL0501 和 AD5290 两个不同型号芯片时，**严禁直接修改配置寄存器**，必须遵循以下标准时序：

1. **复位进入**：清零 `SPCR1.RRST`、`SPCR2.XRST`、`SPCR2.GRST`。
2. **修改参数**：根据目标 DAC 写入对应的极性、相位、波特率。
3. **复位释放**：先置位 `GRST`，等待 2 个时钟；再置位 `XRST`、`RRST`。
4. **强制延时**：执行 `DELAY_US(1~2)`，等待硬件状态机完全就绪。
5. **启动传输**：拉低对应 GPIO CS 管脚 -> 写入 `DXR1` 数据。
6. **安全等待**：**禁止使用延时死等发送完成，必须 `while(SPCR1.bit.RRDY == 0)` 死等接收完成标志**，随后拉高 GPIO CS。

### 4.3 中断优先级与嵌套法则

* **优先级排序**：硬件默认分组 Timer0(Group 1) > DMA(Group 7) > CAN(Group 9)。
* **嵌套规则**：**全系统严格禁止中断嵌套！**
* **设计原则**：依靠 F28335 的硬件 PIE 自动排队机制处理并发中断。由于所有中断内代码（CAN, DMA, 50us 定时器）均无 `while` 死循环，总执行时间极短（< 5µs），不会导致任何数据丢失或实时性破坏。严禁在中断内执行延时、浮点除法或 Modbus 解析。

## 5. 架构优势总结

1. **极高稳定性**：避免了长时间采样导致 RAM 堆栈溢出的致命风险。
2. **绝对时序同步**：将绝对时间（如 200ms）转化为物理点数（如 10kHz 下的 2000 个点），消除了 CPU 定时器与 ADC 采样之间的相位差（Jitter）。
3. **响应极快**：上位机既可以 0 延迟获取“最新实时单点采样”，也能在触发后精准获取“指定时间段的均值”。
4. **扩展性强**：ModbusTCP 与底层硬件采集彻底解耦，后续增加更多的 Modbus 寄存器或算法，无需改动底层采样时序。
